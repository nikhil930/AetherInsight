AetherInsight

Streams of noise become one diagnosed incident.

A distributed, real-time log analyzer with asynchronous LLM root-cause analysis. Producers push logs; the pipeline detects storms of structurally-similar errors and escalates exactly one to a language model for diagnosis.

Filter's decision engine · three Redis primitives

Every raw log runs through this triad. The answers combine into one of four outcomes.

win:<svc>:<fp> ZSET · Lua
Am I over threshold right now? ZADD · ZREMRANGEBYSCORE · ZCARD · atomic in one script
claim:<fp> SET NX EX
Has anyone already escalated this? SET claim NX EX 900 · one-shot mutex · self-releasing
ctx:<fp> LIST
What samples should the LLM see? LPUSH · LTRIM 0 19 · newest 20 first
02

Every log resolves to one of four outcomes

deterministic · single-writer per service
Counted Below threshold — recorded, sample buffered. ZADD win · LPUSH ctx
Escalated Threshold crossed and claim won — kick off LLM analysis. SET NX ok · produce ai-req
Suppressed Threshold crossed but claim already held — increment silently. SET NX no · UPDATE row
Dropped Undecodable poison pill — logged, never rethrown. route → dead-letter
03

Three decisions the whole system rests on

non-obvious calls, deliberately made
Ordering rule

Count before deduplicate

Deduplication guards the expensive LLM call, not the count. If we dedup first, the very storms we exist to detect get suppressed at event #2 and never cross the threshold.

pipeline invariant · Task 9

Coordination

Kafka partition = distributed mutex

Keying raw-logs by service_id means one filter worker owns one service. No Redlock, no ZooKeeper — the broker is the coordinator, and the mutex comes for free.

infra as invariant · design doc

Testability

Ports & adapters, real infra

Decision logic lives in filter-logic.js, tested against real Redis in milliseconds. filter.js is a thin Kafka adapter with no branching. Mocks lie; real infrastructure doesn't.
